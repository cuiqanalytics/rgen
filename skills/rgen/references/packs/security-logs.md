# Data pack: security-logs (Security logs 1.0.0)

Generated by rgen-cli/site-packs.sh from the pack; edit lookup_data/packs/security-logs/skill.md in cuiqGEN instead.
Read only when `rgen packs list` shows this pack as licensed.

Use for security log data with ground truth: web access logs, SSH auth logs, firewall flows,
cloud audit (CloudTrail-style JSON) and SIEM alerts. A scenario column drives everything: rows
are `normal` or an attack (scans, SQL injection, path traversal, Log4Shell, credential stuffing,
web shells, SSH brute force, port scans, exfiltration, C2 beacons, cloud key abuse, cloud
exfiltration, logging tampering), each mapped to a MITRE ATT&CK technique. Attackers come from a
fixed set of IPs per scenario and strike in bursts, so detections have something to find. IPs and
attackers are random addresses, not threat intelligence.

## Chains (put each driver in its own column, then pass the column)

| Driver column | Dependent providers |
|---|---|
| `sec_scenario(source, attack_rate)` (source: web, auth, network, cloud) | `sec_src_ip(scenario)`, `sec_dst_ip(scenario)`, `sec_is_attack(scenario)`, `sec_technique(scenario)`, `sec_alert_rule(scenario)`, `sec_severity(scenario)`, `sec_cve(scenario)` |
| scenario + src ip | `sec_event_time(scenario, ip)` (optional `start_at`, `span_days`) |
| scenario (web) | `sec_http_method`, `sec_path`, `sec_http_status`, `sec_user_agent`, `sec_referrer` |
| status | `sec_response_bytes(status)` |
| scenario (auth) | `sec_ssh_user(scenario)`, then `sec_ssh_outcome(scenario, user)` |
| scenario (network) | `sec_dst_port(scenario)` → `sec_protocol(port)`; `sec_fw_action(scenario)` → `sec_bytes_out(scenario, action)` |
| scenario (cloud) | `sec_cloud_event(scenario)` → `sec_cloud_service(event)`; `sec_cloud_user(scenario)`, `sec_cloud_error(scenario)` |
| technique | `sec_technique_name(technique)`, `sec_tactic(technique)` |
| cve | `sec_cve_vendor(cve)`, `sec_cve_product(cve)`, `sec_cve_name(cve)`, `sec_cve_ransomware(cve)` |
| ip | `sec_ip_registry(ip)` (ARIN, RIPE NCC, APNIC, LACNIC, AFRINIC or private) |

Log-line formatters (deterministic, take the field columns): `sec_access_log(ip, ts, method, path,
status, bytes, ua, referrer)`, `sec_auth_log(ts, host, ip, user, outcome)`, `sec_firewall_log(ts,
host, action, protocol, src, dst, port, bytes)`, `sec_cloud_audit_json(ts, event, user, ip, region, error)`.

Standalone: `sec_public_ip`, `sec_internal_ip`, `sec_host` (or `sec_host('db')`), `sec_cloud_region`,
`sec_alert_status`, `sec_any_technique`, `sec_cve` (any KEV CVE).

## Recipes

```bash
rgen run -n 2000 -p "sec_scenario('web',0.1) as scenario;sec_src_ip(scenario) as ip;sec_event_time(scenario,ip) as ts;sec_http_method(scenario) as method;sec_path(scenario) as path;sec_http_status(scenario) as status;sec_user_agent(scenario) as ua;sec_is_attack(scenario) as is_attack;sec_technique(scenario) as technique" web.csv
```

```toml
[[tables]]
name = "ssh_auth"
rows = 5000

  [tables.columns]
  scenario  = { derived = "rand_sec_scenario('auth', 0.3)" }
  src_ip    = { derived = "CASE WHEN scenario = 'normal' THEN rand_sec_internal_ip() ELSE rand_sec_src_ip(scenario) END" }
  ts        = { derived = "rand_sec_event_time(scenario, src_ip, TIMESTAMP '2026-03-01', 3)" }
  host      = { provider = "sec_host" }
  login     = { derived = "rand_sec_ssh_user(scenario)" }
  outcome   = { derived = "rand_sec_ssh_outcome(scenario, login)" }
  line      = { derived = "rand_sec_auth_log(ts, host, src_ip, login, outcome)" }
  is_attack = { derived = "rand_sec_is_attack(scenario)" }

[output]
format = "csv"
```

Templates: `security-logs/web-access`, `security-logs/ssh-auth`, `security-logs/firewall`,
`security-logs/cloud-audit`, `security-logs/siem-alerts`. For plain log files, select the `line`
(or `record`) column ordered by `ts`.

## Pitfalls

- Every log column must depend on the same `scenario` column; never nest
  (`sec_path(sec_scenario())` draws a different scenario than the label).
- Pass the source IP to `sec_event_time` so each attacker's rows land in one burst; passing a
  random value spreads attacks evenly and removes the signal.
- Attack shares are per source (`sec_scenario('web', 0.05)`); scenarios from another source never
  appear. `sec_scenario(source, 1.0)` gives attacks only (alert queues).
- For SSH and firewall logs, normal sources should be internal (`sec_internal_ip`); `sec_src_ip`
  gives public clients for normal rows (web and cloud).
- ATT&CK IDs follow the bundled release (e.g. cloud logging tampering is T1685.002, formerly
  T1562.008). Keep MITRE's notice (in the pack's sources) when sharing generated datasets that
  include technique names.

## All providers

Use in `-p` without the `rand_` prefix; in TOML `derived` expressions with it.

- `sec_access_log(ip,ts,method,path,status,bytes,ua,ref)`: NGINX/Apache combined log line from its fields — dependent: sec_access_log(ip, ts, method, path, status, bytes, user_agent, referrer)
- `sec_alert_rule(scen)`: detection rule name that fires for a scenario — dependent: sec_alert_rule(scenario)
- `sec_alert_status()`: SOC alert workflow status
- `sec_any_technique()`: any MITRE ATT&CK Enterprise technique or sub-technique ID
- `sec_auth_log(ts,host,ip,login,outcome)`: syslog sshd line (auth.log) from its fields — dependent: sec_auth_log(ts, host, ip, user, outcome)
- `sec_bytes_out(scen,action)`: bytes sent in a flow: tens of MB for exfiltration, small fixed-size C2 beacons, 0 when denied — dependent: sec_bytes_out(scenario, action)
- `sec_cloud_audit_json(ts,api,principal,ip,region,err)`: CloudTrail-style JSON audit record from its fields — dependent: sec_cloud_audit_json(ts, event, user, ip, region, error)
- `sec_cloud_error(scen)`: error code of a cloud API call or NULL on success (attackers probing permissions hit AccessDenied) — dependent: sec_cloud_error(scenario)
- `sec_cloud_event(scen)`: cloud API call name (CloudTrail-style: GetObject, AssumeRole, CreateAccessKey, StopLogging, ...) for a scenario — dependent: sec_cloud_event(scenario)
- `sec_cloud_region()`: cloud region code
- `sec_cloud_service(api)`: service endpoint of a cloud API call (s3.amazonaws.com, iam.amazonaws.com, ...) — dependent: sec_cloud_service(event)
- `sec_cloud_user(scen)`: calling principal (IAMUser:name or AssumedRole:name); attacks use a few compromised identities — dependent: sec_cloud_user(scenario)
- `sec_cve(scen)`: CVE from the CISA Known Exploited Vulnerabilities catalog; with a scenario, the CVE that scenario exploits (Log4Shell: CVE-2021-44228) or NULL
- `sec_cve_name(cve_id)`: vulnerability name of a KEV CVE — dependent: sec_cve_name(cve)
- `sec_cve_product(cve_id)`: affected product of a KEV CVE — dependent: sec_cve_product(cve)
- `sec_cve_ransomware(cve_id)`: true when CISA lists known ransomware use of the CVE — dependent: sec_cve_ransomware(cve)
- `sec_cve_vendor(cve_id)`: vendor of a KEV CVE — dependent: sec_cve_vendor(cve)
- `sec_dst_ip(scen)`: destination IP for a network flow: external hosts for outbound traffic, attacker infrastructure for exfiltration and C2, internal hosts for scans — dependent: sec_dst_ip(scenario)
- `sec_dst_port(scen)`: destination port: common services for normal flows, sweeps across the range for port scans, 443/53/22 for exfiltration — dependent: sec_dst_port(scenario)
- `sec_event_time(scen,actor,start_at,span_days)`: event timestamp: normal traffic follows the working day, each attacker hits in one burst (C2 beacons every minute) within the window start_at + span_days — dependent: sec_event_time(scenario, src_ip)
- `sec_firewall_log(ts,host,action,proto,src,dst,dport,bytes)`: key=value firewall log line from its fields — dependent: sec_firewall_log(ts, host, action, protocol, src_ip, dst_ip, dst_port, bytes)
- `sec_fw_action(scen)`: firewall decision allow or deny (scans mostly denied, exfiltration and C2 slip through) — dependent: sec_fw_action(scenario)
- `sec_host(role)`: server hostname (web-01, db-02, bastion-01, ...); role web, app, db, bastion, ci or any
- `sec_http_method(scen)`: HTTP method typical of a scenario (credential stuffing POSTs, scanners GET/HEAD) — dependent: sec_http_method(scenario)
- `sec_http_status(scen)`: HTTP status for a scenario (mostly 200 for people, 404 for scanners, 401 for credential stuffing) — dependent: sec_http_status(scenario)
- `sec_internal_ip()`: internal (RFC 1918) host address in 10.0.0.0/16
- `sec_ip_registry(ip)`: regional internet registry (ARIN, RIPE NCC, APNIC, LACNIC, AFRINIC) whose space contains an IP, or private — dependent: sec_ip_registry(ip)
- `sec_is_attack(scen)`: ground-truth label: true for attack rows — dependent: sec_is_attack(scenario)
- `sec_path(scen)`: request path: site pages and API calls for normal traffic, probes and URL-encoded payloads for attacks — dependent: sec_path(scenario)
- `sec_protocol(port)`: transport protocol for a port (UDP for DNS and NTP) — dependent: sec_protocol(port)
- `sec_public_ip()`: public IPv4 address from space allocated to a regional registry, weighted by traffic share
- `sec_referrer(scen)`: Referer header value or - — dependent: sec_referrer(scenario)
- `sec_response_bytes(status)`: response size in bytes for an HTTP status — dependent: sec_response_bytes(status)
- `sec_scenario(src,attack_rate)`: normal or an attack scenario for a log source (web, auth, network, cloud); attack_rate is the attack share (default 0.05) — e.g. sec_scenario('auth', 0.1)
- `sec_severity(scen)`: alert severity (low, medium, high, critical) of a scenario — dependent: sec_severity(scenario)
- `sec_src_ip(scen)`: source IP for a scenario: random public clients for normal traffic, a recurring attacker set per attack, compromised internal hosts for exfiltration and C2 — dependent: sec_src_ip(scenario)
- `sec_ssh_outcome(scen,login)`: sshd result: Accepted publickey/password, Failed password, or Invalid user for names that do not exist; rare successful brute force — dependent: sec_ssh_outcome(scenario, user)
- `sec_ssh_user(scen)`: SSH login name: staff and service accounts, or the usual brute-force wordlist (root, admin, oracle, pi, ...) — dependent: sec_ssh_user(scenario)
- `sec_tactic(tid)`: ATT&CK tactic of a technique (first one listed) — dependent: sec_tactic(technique)
- `sec_technique(scen)`: MITRE ATT&CK technique ID of a scenario (T1110.001, T1190, ...), NULL for normal — dependent: sec_technique(scenario)
- `sec_technique_name(tid)`: ATT&CK technique name — dependent: sec_technique_name(technique)
- `sec_user_agent(scen)`: User-Agent: browsers and crawlers for normal traffic, scanners, sqlmap or JNDI payloads for attacks — dependent: sec_user_agent(scenario)

## Templates

Print one with `rgen templates <pack>/<name> > file.toml`, edit, then `rgen run --config file.toml out.duckdb`.

- `security-logs/cloud-audit`: CloudTrail-style JSON audit events with key abuse, bulk storage downloads and logging tampering by compromised identities
- `security-logs/firewall`: Firewall flow log with port scans, large exfiltration transfers and periodic C2 beacons from compromised hosts
- `security-logs/siem-alerts`: SOC alert queue: detections with rule, severity, ATT&CK technique and tactic, attacker IP, host, CVE and triage status
- `security-logs/ssh-auth`: sshd auth.log with SSH brute force bursts (invalid users, failed passwords, a rare success) among normal key-based logins
- `security-logs/web-access`: NGINX combined access log with 5% labelled attacks (scans, SQL injection, traversal, Log4Shell, credential stuffing, web shells) in bursts per attacker
