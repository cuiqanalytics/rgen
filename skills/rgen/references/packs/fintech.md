# Data pack: fintech (Fintech & Payments 1.0.0)

Generated by rgen-cli/site-packs.sh from the pack; edit lookup_data/packs/fintech/skill.md in cuiqGEN instead.
Read only when `rgen packs list` shows this pack as licensed.

Use for test payment cards, IBAN/BIC and other bank identifiers, merchant/card transactions
and accounting ledgers. Values pass real validators (Luhn, IBAN mod-97 with national check
digits for 17 countries, ABA, CLABE) but are random: never present them as real accounts.

## Chains (put each driver in its own column, then pass the column)

| Driver column | Dependent providers |
|---|---|
| `fin_card_network` | `fin_card_number(network)` → `fin_masked_pan(card)`, `fin_card_network_of(card)`; `fin_card_cvv(network)` |
| `fin_iban_country` | `fin_iban_for(country)`, `fin_bic(country)`, `fin_currency_of(country)`; `fin_iban_pretty(iban)` |
| `fin_mcc` | `fin_mcc_category(mcc)`, `fin_mcc_description(mcc)`, `fin_merchant_name(mcc)` → `fin_descriptor(merchant)`; `fin_amount(mcc)` |
| `fin_entry_type` | `fin_debit_account(t)`, `fin_credit_account(t)`, `fin_entry_amount(t)`, `fin_entry_description(t, 'es')`; `fin_account_name(code, 'es')` |

Standalone: `fin_iban`, `fin_any_card_number`, `fin_card_expiry`, `fin_aba_routing`,
`fin_us_account_number`, `fin_clabe` → `fin_clabe_bank(clabe)`, `fin_any_mcc`, `fin_auth_code`,
`fin_decline_reason`, `fin_account_code`.

## Recipes

```bash
rgen run -n 1000 -p "fin_card_network as network;fin_card_number(network) as card;fin_card_cvv(network) as cvv;fin_card_expiry as expiry" cards.csv
rgen run -n 1000 -p "fin_iban_country as country;fin_iban_for(country) as iban;fin_bic(country) as bic;fin_currency_of(country) as currency" accounts.csv
rgen run -n 5000 -p "fin_mcc as mcc;fin_mcc_category(mcc) as category;fin_merchant_name(mcc) as merchant;fin_descriptor(merchant) as descriptor;fin_amount(mcc) as amount" spend.csv
```

```toml
[[tables]]
name = "journal"
rows = 1000

  [tables.columns]
  entry_id      = { provider = "uuid", primary_key = true }
  posted_on     = { provider = "date" }
  entry_type    = { provider = "fin_entry_type" }
  debit_account = { derived = "rand_fin_debit_account(entry_type)" }
  credit_account = { derived = "rand_fin_credit_account(entry_type)" }
  amount        = { derived = "rand_fin_entry_amount(entry_type)" }

[output]
format = "duckdb"
```

For full card or ledger datasets start from a template (`rgen templates fintech/card-transactions`)
and edit it rather than writing the config from scratch.

## Pitfalls

- `fin_card_number(fin_card_network())` (a provider nested inside another) gives wrong or NULL
  values. Generate the network as a column first, as in the recipes.
- `fin_amount(mcc)` is in USD with a per-category ticket size; scale it in a `derived` column for
  other currencies.
- Only 17 countries get national check digits inside the account number; the others are valid
  IBANs with random account numbers (validators accept them).

## All providers

Use in `-p` without the `rand_` prefix; in TOML `derived` expressions with it.

- `fin_aba_routing()`: US ABA routing number with valid check digit
- `fin_account_code()`: chart-of-accounts code
- `fin_account_name(acct,locale)`: account name for a code, locale en or es — dependent: fin_account_name(code)
- `fin_amount(code)`: card transaction amount (USD) with a realistic lognormal ticket size for an MCC — dependent: fin_amount(mcc)
- `fin_any_card_number()`: Luhn-valid test card number, networks in a US consumer mix
- `fin_any_mcc()`: any of 981 merchant category codes, uniform
- `fin_auth_code()`: 6-character authorization code
- `fin_bic(cc)`: well-formed BIC/SWIFT code for a country — dependent: fin_bic(country_code)
- `fin_card_cvv(net)`: card security code, 4 digits for American Express — dependent: fin_card_cvv(network)
- `fin_card_expiry()`: card expiry MM/YY, 1 to 60 months ahead
- `fin_card_network()`: card network (Visa, Mastercard, American Express, ...), US consumer mix
- `fin_card_network_of(num)`: card network detected from a card number — dependent: fin_card_network_of(card_number)
- `fin_card_number(net)`: Luhn-valid test card number for a network column — dependent: fin_card_number(network)
- `fin_clabe()`: Mexican CLABE (18 digits, real bank code, valid check digit)
- `fin_clabe_bank(clabe)`: bank name of a CLABE — dependent: fin_clabe_bank(clabe)
- `fin_credit_account(etype)`: account credited by an entry type — dependent: fin_credit_account(entry_type)
- `fin_currency_of(cc)`: ISO 4217 currency of accounts in an IBAN country (EUR for DE, GBP for GB, ...) — dependent: fin_currency_of(country)
- `fin_debit_account(etype)`: account debited by an entry type — dependent: fin_debit_account(entry_type)
- `fin_decline_reason()`: card decline reason, realistic mix
- `fin_descriptor(merchant)`: card statement descriptor, e.g. SQ *GREEN MARKET #0412 — dependent: fin_descriptor(merchant)
- `fin_entry_amount(etype)`: amount for a journal entry type (lognormal) — dependent: fin_entry_amount(entry_type)
- `fin_entry_description(etype,locale)`: description of a journal entry type, locale en or es — dependent: fin_entry_description(entry_type)
- `fin_entry_type()`: journal entry type (credit_sale, supplier_payment, payroll_accrual, ...) weighted by frequency
- `fin_iban()`: valid IBAN for a random IBAN country, weighted toward SEPA economies
- `fin_iban_country()`: country code using IBANs, weighted toward SEPA economies
- `fin_iban_for(cc)`: valid IBAN (mod-97 check digits, country BBAN format, national check digits for 17 countries) for a country code column — dependent: fin_iban_for(country)
- `fin_iban_pretty(iban)`: IBAN printed in groups of four — dependent: fin_iban_pretty(iban)
- `fin_masked_pan(num)`: PCI-style masked card number (first 6, last 4) — dependent: fin_masked_pan(card_number)
- `fin_mcc()`: merchant category code weighted by consumer card activity
- `fin_mcc_category(code)`: spend category of an MCC (Groceries, Restaurants, Fuel, Travel, ...; card-network range name for other codes) — dependent: fin_mcc_category(mcc)
- `fin_mcc_description(code)`: description of an MCC — dependent: fin_mcc_description(mcc)
- `fin_merchant_name(code)`: plausible fictional merchant name for an MCC — dependent: fin_merchant_name(mcc)
- `fin_us_account_number()`: US bank account number, 8-12 digits

## Templates

Print one with `rgen templates <pack>/<name> > file.toml`, edit, then `rgen run --config file.toml out.duckdb`.

- `fintech/bank-accounts`: Bank accounts across countries: IBAN and BIC for SEPA and others, ABA routing for US, CLABE for Mexico
- `fintech/card-transactions`: Customers, cards and card transactions with MCC mix, merchants, amounts, declines and fraud flags
- `fintech/ledger`: Double-entry general ledger: chart of accounts and balanced journal entries (debits = credits)
- `fintech/payment-lifecycle`: Payment event log: authorized, captured, settled, refunded, disputed, chargeback
