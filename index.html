Tables that reference each other

Describe a schema in TOML: foreign keys, category mixes, skewed amounts, computed columns. rgen builds parents before children, so every reference points at a row that exists.

[[tables]]
name = "customers"
rows = 2000
    [tables.columns]
    customer_id = { provider = "uuid", primary_key = true }
    name        = { provider = "name" }
    country     = { provider = "choice",
                    distribution = "weighted",
                    params = { values = ["US", "UK", "DE", "MX"],
                               weights = [0.5, 0.2, 0.2, 0.1] } }

[[tables]]
name = "orders"
rows = 20000
    [tables.columns]
    order_id    = { provider = "uuid", primary_key = true }
    customer_id = { provider = "choice",
                    reference = "customers.customer_id" }
    ordered_at  = { provider = "date",
                    params = { from = "2025-01-01", to = "2025-12-31" } }
    amount      = { provider = "amount",
                    distribution = "lognormal",
                    params = { min = 5, max = 2000,
                               median = 60, std_dev = 40 } }
$ rgen run --config shop.toml shop.duckdb
  ✓ customers: 2000 rows
  ✓ orders: 20000 rows
$ duckdb shop.duckdb -c "
    SELECT c.country, count(*) AS orders,

A twin of your real data, without the real data

Point rgen twin at a CSV, Parquet, SQLite or DuckDB file. It profiles each column (distribution shape, category mix, date range, ID pattern) and generates a fresh dataset with the same shape. Share it with contractors, put it in CI, demo with it. Not a single real row comes along.

Want to adjust the result first? rgen profile sales.csv prints the config it inferred.

$ rgen twin --scale 2.0 sales.csv twin.duckdb
Profiling sales.csv...
Generating synthetic twin → twin.duckdb
  ✓ data: 10000 rows

Data packs

Packs add curated reference data, new providers and ready-made templates on top of the free CLI. Every pack is checked with automated tests, and identifiers are verified with independent validators.

How packs work

  1. Email us the pack you want. We reply with a license key and the pack file.
  2. Install both:
    $rgen license install <KEY> && rgen packs install ./fintech.rgenpack
  3. Use it: the pack's providers show up in rgen providers, and its configs in rgen templates.
    $rgen templates fintech/card-transactions > cards.toml && rgen run --config cards.toml cards.duckdb

Licenses are checked offline. If one lapses, the pack stops loading; the free CLI and everything you already generated stay yours.

Questions

Is any of the generated data real?

No. Every row is generated. Reference lists such as city names, occupations, merchant categories and wage statistics come from public datasets, but the people, accounts and IDs are random. A generated ID can still match a real one by chance, so never use it to contact, verify or charge anyone.

Can I use the data commercially?

Yes. The data you generate is yours: put it in demos, tests, docs or products. rgen packs info <pack> lists the public sources inside each pack and their licenses.

Does rgen need internet access or an account?

No. It's a single binary that runs offline, and pack licenses are verified offline too. No telemetry.

Does it run on macOS and Windows?

The native binary is for Linux (x86-64). On macOS and Windows, use the Docker image: docker pull ghcr.io/cuiqanalytics/rgen.

Are the IDs and bank numbers valid?

Pack identifiers pass the same checks real systems use: Luhn for cards, IBAN mod-97 with national check digits, US routing numbers, CLABE, and the check digits of RUT, CUIT, CURP, RFC, CPF, CNPJ, NIT, RUC and CI. We test them against python-stdnum and schwifty on every pack build.

What happens when a pack license expires?

That pack stops loading. Everything else keeps working, and data you already generated is unaffected.

How do I buy a pack?

Email rodrigo.abt@gmail.com with the pack you want. You'll get a license key and the pack file, usually within a business day. Card checkout is coming.

Can I get a refund, a team license or an invoice?

Yes. Write to us and we'll sort it out.

Can an AI assistant use rgen?

Yes. Install the Claude Code skill and ask for the data you need; Claude picks the providers or writes the TOML config and runs rgen for you.
