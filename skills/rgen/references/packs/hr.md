# Data pack: hr (HR & Workforce 1.0.0)

Generated by rgen-cli/site-packs.sh from the pack; edit lookup_data/packs/hr/skill.md in cuiqGEN instead.
Read only when `rgen packs list` shows this pack as licensed.

Use for employees, org charts, job titles, skills and salaries. Occupations, titles, tasks and
skills come from O*NET; salaries from the BLS OEWS May 2025 data (annual USD, US states).

## Chains (put each driver in its own column, then pass the column)

| Driver column | Dependent providers |
|---|---|
| `hr_department` | `hr_soc_code_in(department)` (individual contributors) or `hr_manager_soc_code_in(department)` |
| soc code (from the above, or `hr_soc_code`) | `hr_job_title(soc)`, `hr_occupation(soc)`, `hr_task(soc)`, `hr_tech_skill(soc)`, `hr_knowledge(soc)`, `hr_education(soc)`, `hr_job_zone(soc)`, `hr_salary(soc)` |
| `hr_department` | `hr_level_for(department)`: a level that fits the department (management levels for Executive) |
| soc + level (`hr_level_for`, `hr_seniority` or `hr_management_level`) | `hr_salary_for(soc, level)` |
| soc + level + `state_code` | `hr_salary_in(soc, level, state)` |

Standalone: `hr_any_job_title`, `hr_employment_type`, `hr_candidate_source`.

## Recipes

```bash
rgen run -n 1000 -p "hr_department as department;hr_soc_code_in(department) as soc;hr_job_title(soc) as title;hr_level_for(department) as level;state_code as state;hr_salary_in(soc,level,state) as salary" staff.csv
```

## Pitfalls

- `hr_soc_code_in(hr_department())` (nested) can fail with "More than one row returned"; keep
  the department as its own column.
- In the org-chart pattern the foreign key must not share a name with the manager table's key
  (`reports_to`, not `manager_id`), or the department lookup self-matches.
- `hr_seniority` alone gives Executive staff titles like "Chief Executive, Junior"; use
  `hr_level_for(department)` whenever a department column exists.
- Salaries are US figures; for other countries convert or scale in a `derived` column.

## All providers

Use in `-p` without the `rand_` prefix; in TOML `derived` expressions with it.

- `hr_any_job_title()`: job title from 54k real-world titles across all occupations
- `hr_candidate_source()`: recruiting source of a candidate
- `hr_department()`: company department, weighted by typical headcount share
- `hr_education(soc)`: typical education for an occupation — dependent: hr_education(soc_code)
- `hr_employment_type()`: employment type (Full-time, Part-time, Contractor, Intern)
- `hr_job_title(soc)`: real-world job title for an occupation code — dependent: hr_job_title(soc_code)
- `hr_job_zone(soc)`: O*NET job zone 1-5 (preparation needed) of an occupation — dependent: hr_job_zone(soc_code)
- `hr_knowledge(soc)`: knowledge area important to an occupation, weighted by importance — dependent: hr_knowledge(soc_code)
- `hr_level_for(dept)`: level that fits a department: management levels (Team Lead to C-level) for Executive, Intern to Principal elsewhere — dependent: hr_level_for(department)
- `hr_management_level()`: management level (Team Lead to C-level), pyramid-shaped mix
- `hr_manager_soc_code_in(dept)`: management occupation code for a department — dependent: hr_manager_soc_code_in(department)
- `hr_occupation(soc)`: standard occupation name for an occupation code — dependent: hr_occupation(soc_code)
- `hr_salary(soc)`: annual salary (USD) drawn from the occupation's BLS wage distribution — dependent: hr_salary(soc_code)
- `hr_salary_for(soc,lvl)`: annual salary (USD) for an occupation at a seniority or management level, e.g. hr_salary_for(soc_code, seniority)
- `hr_salary_in(soc,lvl,st)`: annual salary (USD) for an occupation and level, adjusted to a US state, e.g. hr_salary_in(soc_code, seniority, state_code)
- `hr_seniority()`: individual-contributor level (Intern to Principal), realistic mix
- `hr_soc_code()`: O*NET-SOC occupation code of a typical company role, e.g. 15-1252.00
- `hr_soc_code_in(dept)`: individual-contributor occupation code in a department, weighted by headcount — dependent: hr_soc_code_in(department)
- `hr_task(soc)`: core work task of an occupation — dependent: hr_task(soc_code)
- `hr_tech_skill(soc)`: software/technology skill used in an occupation, hot technologies favored — dependent: hr_tech_skill(soc_code)

## Templates

Print one with `rgen templates <pack>/<name> > file.toml`, edit, then `rgen run --config file.toml out.duckdb`.

- `hr/compensation`: Employees with level- and state-adjusted salaries from BLS wage data, plus bonus targets
- `hr/employees`: Employee roster: department, occupation, title, level, skills, education
- `hr/org-chart`: Managers and the employees reporting to them, departments kept consistent
- `hr/recruiting-pipeline`: Candidate funnel event log: applied, screened, interviewing, offer, hired/rejected
